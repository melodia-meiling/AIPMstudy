## 四、必须处理的问题

### 4.1 【P0】智能体搭建步数冲突

**同一件事，你的两份资产给的答案不一样**：

| 来源 | 步骤 |
|---|---|
| Demo 界面 | **6 步**：创建智能体 → 写系统提示词 → 配知识库 → 加插件 → 设计工作流 → **发布** |
| 知识树 `t4-3-4` | **8 步法**：选模型获取 API Key → 写人设 Prompt → 配知识库 RAG → 配工具调用 → 设计工作流 → **做用户界面** → 测试迭代 → 部署上线 |
| 知识树 `t7-2` | **7 步法**：创建智能体 → 配置人设 Prompt → 配知识库 RAG → **配置工作流** → 配置插件工具 → 调试测试 → 发布 |

**三个版本，步数各不相同。** 这跟书单资料里"6 章 vs 12 章"是同一类问题，而且这次出现在**你自己产品的正中央**——用户点"智能体搭建指引"看到的，和问智能体得到的，可能对不上。

**额外发现两个真实的技术矛盾**：

1. **"插件"和"工作流"的顺序，知识树内部就自相矛盾**：
   - `t7-2` 是"先工作流（第 4 步）后插件（第 5 步）"
   - `t4-3-4` 是"先工具（第 4 步）后工作流（第 5 步）"
   这两个顺序**不能随意颠倒**——工作流里需要调用插件节点，先设计工作流再补插件，往往要回头改工作流。

2. **"FDE"被用了两次，含义完全不同**：
   - `t2-2-12`：FDE = Full-Disk Encryption（全盘加密）
   - `t2-3-4`：FDE = Feature-Driven Development（特性驱动开发）
   
   两个都是真实存在的，但**放同一个缩写在同一份知识树里，零基础用户必然混淆**。必须加区分前缀。

**建议**：统一为一套步法。我倾向这样合并（6 步用于**界面展示**，8 步用于**深入讲解**）：

```
界面展示版（6 步，面向"我要开始搭"）
1 定场景      ← 新增，最重要，当前缺失
2 选模型
3 写提示词
4 配知识库
5 接工具 + 编排工作流   ← 合并，避免顺序争议
6 测试调优 → 发布
```

**注意：我上一轮写的 `03` 和 `05` 里用的是"六步法"，同样需要按这套统一。这是我自己引入的第四个版本，一并纠正。**

### 4.2 【P0】知识树没进知识库

现在知识树是死的 HTML。要做的事：

- [ ] 用 `06_知识树结构化导出.md`（370 行）作为知识库主体内容
- [ ] 116 个知识点**按知识点切片**（一点一片），不要按主干切
- [ ] 保留 `掌握程度` 和 `关联概念` 字段一起入库——前者是用户最需要的判断依据，后者是跳转线索

### 4.3 【P0】知识库双库分离

**不要**把 13 本书单和 116 个知识点混在一个知识库里。混在一起的结果是：用户问"什么是 RAG"，检索可能返回"《某某书》讲了 RAG 相关内容"。

| 知识库 | 内容 | 路由条件 |
|---|---|---|
| 主库 | 116 个知识点 + 六步法 | 默认检索 |
| 辅助库 | 13 本书单 + 标签 + 适合人群 | 仅当用户问"读什么书/推荐书" |

### 4.4 【P1】Demo 缺"诊断"与"巩固"

| 缺失 | 后果 |
|---|---|
| 开场诊断（现状/目标/时间） | 4 个入口选了之后直接进内容，没有个性化 |
| 每次回答结尾的追问 | 用户看完不知道下一步 |
| 进度回写 | 学习看板有进度，但和对话不联动 |
| "你现在不用深究"的减法指引 | 116 个知识点会让零基础用户焦虑 |

**第 4 条特别重要**：知识树 116 个点，按掌握程度精确分布为 **🔴必学 35 · 🟡需理解 35 · ⚪了解即可 46**（脚本核准）。这个比例（35 / 116）是**极好的安抚素材**，应该在对话里主动用：

> "这 116 个知识点里，真正要掌握的只有 35 个，剩下 81 个知道有这回事就行。"

### 4.5 【P1】内容缺口（我上一轮说"痛点内容全空"，要修正）

修正后的说法：**痛点①（产品 0→1）在知识树里其实覆盖得不错**——主干 7 有完整的 5 步流程（用户调研→需求分析→方案设计→测试迭代→上线发布）。

**真正还缺的是**：

- [ ] **AI 可行性判断**：什么问题该用 AI、什么不该用（知识树里没有）
- [ ] **AI 产品 vs 传统产品的差异**：不确定性管理、数据驱动迭代（散落在几条里，没有独立讲解）
- [ ] **完整案例拆解**：知识树里只有项目方向，没有从头到尾拆一个
- [ ] **零基础术语表**：知识树有 116 条解释，但缺一份"最常被问的 20 个词"速查
- [ ] **面试题对应答案**：`t5-2-2` 列了 7 个高频题，但没有答案

### 4.6 【P1】Python 模块可以做减法

主干 6 有 **19 个知识点**讲 Python（变量、if/else、for、函数、import……），但你自己在 `t4-2-4` 里写了"产品经理不要求独立写完整系统"。

**19 个点占了知识树的 16%**，对零基础转行者来说性价比可疑。建议：
- 保留：`t6-1-3 怎么快速读一段代码`、`t6-2-4 函数 def`、`t6-4 沟通必备术语`（6 条）
- 其余标"了解"，并在对话中主动说"这个你现在可以跳过"
