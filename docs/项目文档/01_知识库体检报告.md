# AIPM 学习工作台 · 知识库体检报告

> 体检对象：工作区现有 3 份整理资料（coze / deepseek / 豆包）
> 体检日期：2026-09-10
> 体检依据：目标用户两大核心痛点 —— ①搞不懂 AI 产品 0→1 完整运行逻辑；②不理解智能体搭建的底层逻辑与完整流程
> 说明：本报告只基于现有资料，不涉及 Demo 产品设计。

---

## 一、结论先行

现有知识库**不是"知识库"，是"书单目录"**。

它回答的是"市面上有哪些 AI 产品经理的书、大概讲什么"，
而不是用户真正要问的"我现在该做什么、下一步做什么"。

**核心矛盾**：用户带着"我要转行、我要搭智能体"这种**任务型问题**进来，
而知识库只能给出**目录型答案**。这个错配是检索不准的根本原因——不是切片参数没调好，是内容层级不够。

| 评估维度 | 现状 | 判定 |
|---|---|---|
| 内容粒度 | 每书 1 段总结 + 章标题 | 太粗，无法回答"怎么做" |
| 结构一致性 | 三份资料体例各不相同 | 不统一，难切片 |
| 时效性 | 含 2025-2026 新书 | 尚可 |
| 覆盖度 vs 用户痛点 | 痛点①②几乎空白 | **致命缺口** |
| 数据质量 | 存在重复与自相矛盾 | 需清洗 |
| 元数据完整度 | 缺"解决什么问题"标签 | 检索命中率低 |

## 二、致命问题：书目重复且自相矛盾

### 2.1 重复书目（三份资料宣称 15 本 → 实际 13 个不同书目）

| 书目 | 出现次数 | 出现在 |
|---|---|---|
| 《AI产品经理实战：从大模型集成到商业化落地》 | **3 次** | coze / deepseek / 豆包 |
| 《AI产品经理》（苏博、刘雨霞） | 1 次 | deepseek |
| 《迈向AGI时代：AI产品经理方法论》 | 1 次 | deepseek |
| 《Machine Learning in Production》 | 1 次 | deepseek |
| 《Building ML Powered Applications》 | 1 次 | deepseek |
| 《产品经理的AI设计力》 | 1 次 | 豆包 |
| 《AI产品经理：方法、技术与实战》（王泽楷） | 1 次 | 豆包 |
| 《秒懂智能体：AI Agent重新定义未来工作》 | 1 次 | 豆包 |
| 《人工智能产品设计》 | 1 次 | 豆包 |
| 《Co-Intelligence》 | 1 次 | coze |
| 《Building AI-Powered Products》 | 1 次 | coze |
| 《Designing Machine Learning Systems》 | 1 次 | coze |
| 《The Art of AI Product Development》 | 1 次 | coze |

**影响**：同一本书被切成 3 个不同版本进入知识库，检索时会返回 3 条互相冲突的结果，用户看到的是"这本书到底几章"的困惑，而不是答案。

**顺带纠正一个口径**：三份资料各 5 本，合计 15 条记录，但去掉重复后是 **13 个不同书目**（其中 1 本重复 3 次，1 本重复 2 次）。对外宣传"15 本书"会虚高，建议改成"13 本 + 3 份整理资料"。

### 2.2 同一本书的自相矛盾（最严重）

《AI产品经理实战：从大模型集成到商业化落地》在三份资料中的描述：

| 来源 | 结构描述 | 内容主线 |
|---|---|---|
| 豆包 | 6 章（AI产品简介 / 原型设计 / 技术选型 / 交互体验 / 商业化 / 案例） | 认知-设计-技术-商业化 |
| deepseek | 12 章 | 需求挖掘、原型构建、模型工程、商业应用 |
| coze | 12 章 | 需求挖掘、原型构建、模型工程、商业应用 |

**只有"12 章"这一个信息被两份资料共同确认，且与豆包的"6 章"直接冲突。**

> 这暴露了一个更根本的问题：**这批资料是 AI 生成的二手信息，没有经过原书核对**。
> coze 文件末尾自己标注了"本内容由 Coze AI 生成"。

### 2.3 处理建议（三选一）

- **方案 A（推荐｜成本最低）**：以 **deepseek + coze 交叉确认的"12 章"版本**为准，删除豆包的 6 章版本，并标注"结构信息待原书核对"。
- **方案 B（最稳｜成本高）**：购买/借阅原书，核对目录后再入库。
- **方案 C（最诚实｜推荐配合 A 使用）**：保留矛盾，但在知识库里显式记录"该信息存在两个版本"，并在 Agent 回复时主动说明不确定性。

**产品经理视角的提醒**：哪怕内容是对的，一个"连目录都对不上"的知识库，会让零基础用户直接丧失信任。**宁可少而准，不要多而乱。**

## 三、结构性问题：内容层级与用户痛点错配

### 3.1 用户问题 vs 知识库能力的落差

| 用户真实问题 | 知识库现有内容 | 能否回答 |
|---|---|---|
| "AI 产品从 0 到 1 要做哪些事？" | 各书的章标题（"产品构想与原型设计"） | ❌ 只知道有这一章，不知道怎么做 |
| "智能体搭建的完整流程是什么？" | 《秒懂智能体》的 6 个章节名 | ❌ 只知道书里讲了 Coze/GPTs，不知道步骤 |
| "我该先学什么后学什么？" | 有"阅读顺序建议"（仅 coze 文件） | ⚠️ 部分能，但只针对 5 本英文书 |
| "RAG 和微调有什么区别，我该用哪个？" | 无 | ❌ |
| "转行需要哪些能力？" | 各书有零散描述 | ⚠️ 能拼凑，但不系统 |

**结论**：用户的两个**核心痛点，在知识库里基本是空的**。

### 3.2 现有内容的正确用法

现有资料**不是没用**，但它的定位应该被重新定义：

- ❌ 不是"教用户怎么做 AI 产品"的知识源
- ✅ 是"**帮用户选书、判断该书是否适合自己**"的书目导航层

把它当"学习路径的选书地图"用，检索准确率会立刻提升——因为用户的检索意图会被框定为"选书"，而不是"求解"。

## 四、缺口清单：要补什么

### 4.1 针对痛点①：AI 产品 0→1 全流程（**最高优先级**）

需要新增一类内容，粒度必须是**可执行的步骤**，而不是章标题：

- [ ] **AI 产品全生命周期地图**：从机会识别 → 场景判断 → 需求定义 → 原型验证 → 技术选型 → 开发迭代 → 上线 → 数据回归 → 商业化，每一阶段回答"产出物是什么、判断标准是什么、常踩的坑是什么"
- [ ] **"AI 可行性判断"清单**：什么问题适合用 AI 解决、什么不适合（可参考《AI产品经理实战》2.1 节思路，但需自己补全判断标准）
- [ ] **AI 产品 vs 传统产品差异对照表**：不确定性管理、数据驱动迭代、能力渐进释放（coze 资料已点到，需展开）
- [ ] **3-5 个完整拆解案例**：一个 C 端工具、一个 B 端系统，从痛点到上线全过程逐环节拆解
- [ ] **PRD 模板（AI 版）**：AI 产品的 PRD 与传统 PRD 的差异点

### 4.2 针对痛点②：智能体搭建完整流程（**最高优先级**）

- [ ] **智能体底层原理（零基础版）**：用"人做事"的类比讲清 大模型 / 提示词 / 知识库 / 工具调用 / 工作流 分别扮演什么角色
- [x] ~~**智能体搭建六步法**~~ —— **已完成**，见 `kb_main_六步法.md`（已统一为界面 6 步 / 讲解 8 步）
- [ ] **智能体 vs 传统 API vs 聊天机器人的区别**（《秒懂智能体》第 1 章有涉及，需展开成对照表）
- [ ] **提示词"八要素"体系实操版**（《秒懂智能体》第 2 章提到方法论，知识库需要补可套用的模板）
- [ ] **平台横向对比**：扣子 / 文心一言 / 智谱清言 / GPTs / Dify 各自适合什么场景、门槛如何
- [ ] **扣子平台专项**：扣子本身的搭建流程、能力边界、常见问题（**当前知识库完全没有**，但这是你的实际运行平台）

### 4.3 元数据与标签体系（提升检索命中率的关键）

现有资料缺少**面向检索的标签**。建议给每条知识补上以下字段：

| 字段 | 作用 | 示例 |
|---|---|---|
| `痛点归属` | 直接对应核心痛点 | 痛点①/痛点②/都不属于 |
| `内容类型` | 区分"是什么/为什么/怎么做" | 概念解释 / 方法论 / 操作步骤 / 案例 |
| `用户阶段` | 匹配用户所处阶段 | 0基础认知 / 准备转行 / 已入行 |
| `解答的问题` | **最重要**：用一句用户的问法标注 | "智能体的知识库和模型微调有什么区别？" |
| `可信度` | 标注信息来源 | 原书核对 / AI生成待核 / 本人原创 |

> **`解答的问题` 这一字段是提升检索准确率性价比最高的一招**：
> 它让"用户的口语化提问"和"知识片段"之间有了直接的语言桥梁，比单纯依赖向量相似度更稳。

## 五、优化后的知识库结构建议

建议从"按书组织"改为**"按用户任务组织、按书做引用来源"**：

```
知识库/
├── 00_导航层（用户进来先看什么）
│   ├── 学习路径图（0基础 → 转行 → 上手）
│   └── 我该从哪开始（分诊清单）
│
├── 01_痛点①_AI产品0到1（核心）
│   ├── 全生命周期地图
│   ├── 可行性判断清单
│   ├── AI产品vs传统产品差异
│   └── 案例拆解 ×N
│
├── 02_痛点②_智能体搭建（核心）
│   ├── 底层原理（零基础版）
│   ├── 六步搭建法
│   ├── 提示词体系
│   └── 平台对比 + 扣子专项
│
├── 03_书目导航层（现有资料重组后放这里）
│   ├── 按学习阶段分组
│   ├── 按方向分组（产品/工程/设计）
│   └── 每本书：适合谁 + 解决什么 + 什么时候读
│
└── 04_术语表（零基础用户必备）
    └── 大模型/RAG/微调/Agent/工作流/Token… 用生活化类比解释
```

**关键改动**：现有 15 本资料从"知识库主体"降级为"第 03 层的书目导航"，让位给真正回答用户痛点的 01、02 层。

## 六、需要你确认或补做的三件事

1. **核实那本书的真实目录**（或决定采用哪个版本）——这是当前最大的可信度风险点
2. **补写 01、02 层内容**——这是工作量最大、但决定产品成败的部分。建议你自己写，因为你是目标用户，你的语言最贴合用户
3. **确认扣子的知识库能力边界**——支持什么格式、切片方式、单文件大小上限、是否支持多知识库路由

---

## 七、一句话总结

> 现有知识库的价值在于**"帮人选书"**，而用户需要的是**"教人做事"**。
> 不要试图靠调切片参数解决这个问题——**先把内容层级补上，检索准确率会自然提升**。
