## 二、【必须改】"所有回答必须优先基于 15 本书"这一条

原文：

> 所有回答必须优先基于提供的15本AI产品经理相关专业书籍的大纲、核心内容、方法论与实战案例，确保知识的专业性和系统性。

**问题**：这条会主动破坏你的产品。原因有三个，而且每一条都是硬的：

### 问题 1：数字错了，是 13 本

3 份资料各 5 条记录 = 15 条，去重后是 **13 个不同书目**（《AI产品经理实战》重复 3 次）。你的开场白和知识库模块都写的 13 本。

### 问题 2：那批资料"没有操作细节"，撑不起"必须优先基于"

这是最关键的一点。你的书单资料每本书只有**章节目录 + 一段简介**。它不是知识，是**书目索引**。

真实检验：
- 用户问"什么是 RAG" → 书单能答吗？**不能**，只能答"《XX书》讲了 RAG"
- 用户问"智能体怎么搭" → 书单能答吗？**不能**，只有章节名

**而这两类问题正是你定义的两大核心痛点。**

所以这条规则的实际效果是：**强迫 Agent 用一份答不了核心痛点的资料去回答核心痛点**。结果就是满屏"建议你阅读《XX书》第 3 章"——这恰恰是零基础用户最讨厌的答案。

### 问题 3：你有更好的资产，但这条规则不让用

你的知识树有 **116 个知识点、8900 字正文**，语言是写给零基础人群的（"变量=存数据的盒子""幻觉=一本正经胡说八道"），还带掌握程度分级。**它比书单资料强一个量级。**

但"必须优先基于 15 本书"这条规则，会让 Agent 绕过知识树。

### 建议改法

把知识库分成三层，并明确优先级：

```
主库（优先）：知识树 116 个知识点 —— 回答概念、原理、工具、流程
主库（优先）：统一六步法 —— 回答智能体搭建
辅助库（按需）：13 本书 —— 只在用户问"读什么书"时使用
```

## 三、【必须改】"知识溯源：核心知识点尽量标注对应书籍来源"

原文：

> 知识溯源：核心知识点尽量标注对应的书籍来源，引导学习者延伸阅读

**问题**：你的书单是**书目级别**（每本书只有目录和简介），没有细到知识点。

所以 Agent 无法知道"RAG"这个知识点对应哪本书的哪一章。它只有两个选择：
1. 编一个章节号 —— **直接产生幻觉，违反你自己第 5 条规则**
2. 不标注 —— 违反第 3 条规则

**两条规则互相打架。**

而且知识树里 116 个概念，大部分根本不在 13 本书的目录里。

### 建议改法

把"必须标注来源"改成**有依据才标注**：

```
- 知识树里有对应条目 → 可以说"知识树里有这一条"，并带出掌握程度
- 用户明确问选书 → 引用书目信息，并说明适合阶段
- 两者都没有 → 坦诚说明"这是我基于产品经验的整理"，并标注区分
- 绝不编造章节号
```

## 四、【建议补】缺了对话控制机制

你的 5 条回答规则都是"怎么表达"，但缺"怎么推进对话"。具体缺三样：

### 缺失 1：开场诊断

你的开场白有 4 个背景选项（传统PM / 运营市场 / 学生零基础 / 技术背景）—— 这是**收集了背景信息**，但提示词里没写"拿到背景后该怎么办"。

结果：用户选了背景，Agent 不知道要用这个信息做什么。

### 缺失 2：让用户往前走一步

你的定位是"陪练与知识顾问"。但"顾问"容易变成"有问必答，答完就完"。

零基础转行用户的真实状态是**不知道下一步做什么**，不是"缺一个答案"。所以每条回答应该结束在一个具体动作上。

### 缺失 3：主动做减法

你有 **116 个知识点**。零基础用户看到这个数字的第一反应是"我学不完"，然后放弃。

而你手上有一个极好的数字：**116 个里真正必学的只有 35 个**。这个比例应该主动告诉用户，而不是等他焦虑了再说。

## 五、【建议改】六步法没写进提示词

你 Demo 界面是 6 步（创建→提示词→知识库→插件→工作流→发布），而你的知识树里有两个不同版本（7 步、8 步）。

**提示词里没写用哪一套**，所以 Agent 每次回答可能给出不同步数 —— 用户点"搭建指引"看到的和问出来的对不上。

建议把统一六步法直接写进提示词（短，不占多少字数），确保稳定一致。
