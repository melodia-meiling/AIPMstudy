## 阶段总览

```
阶段 0  准备（不碰平台）        ← 最关键，决定成品质量上限
阶段 1  知识库重构与上传
阶段 2  智能体主体配置
阶段 3  测试与调优
阶段 4  上线与迭代
```

**时间预估**：阶段 0 占 60% 的工作量。
不要跳过它直接去平台里点——**你会做出来一个"看起来能用但没用"的东西**。

### 0.2 【最重要】补写核心内容

这是决定产品成败的一步，也是**只有你能做**的一步。
（因为你是目标用户，你的语言最贴近用户。）

**必须自己写，不能靠 AI 生成的清单**（现状里 AI 生成的资料已经出现了自相矛盾）：

#### A. 主线内容（对应两大痛点）

- [x] ~~**AI 产品 0→1 全流程地图**~~ —— **主要由知识树覆盖**（主干 7「实操从0到1」20 个点）
      知识树的实际结构是 5 阶段：用户调研 → 需求分析 → 方案设计 → 测试迭代 → 上线发布
      **不要用我之前写的"九阶段"**——那是我在没看到知识树时的独立设计，与你的资产冲突
      仍需补：每阶段的"什么算做对 / 新手最容易错在哪"（知识树只有概念解释，缺判断标准）
- [x] ~~**智能体搭建六步法**~~ —— **已完成**，见 `kb_main_六步法.md`
      已统一为"界面 6 步 / 讲解 8 步"，并修掉"插件 vs 工作流"顺序矛盾
- [ ] **底层概念类比表**
      大模型 / 提示词 / 知识库 / 工具 / 工作流 / 微调
      （草表见 `03_功能模块与交互流程.md` 模块 2）
- [ ] **AI 产品 vs 传统产品差异**
      不确定性管理 / 数据驱动迭代 / 能力渐进释放
      （知识树里散落在几条中，无独立讲解 —— 这是真实缺口）
- [ ] **AI 可行性判断清单**
      什么问题适合用 AI 解决、什么不适合 —— **知识树里完全没有，是最大缺口**
- [ ] **零基础术语表**（20-30 个词，每个一句话 + 类比）
      知识树已有 116 条解释，此项只需做"最常被问的 20 个"速查

#### B. 元数据标签（提升检索准确率的关键）

给**每一条**知识片段补上这 5 个字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| `痛点归属` | 痛点①/痛点②/通用 | 痛点② |
| `内容类型` | 概念/方法论/操作步骤/案例 | 操作步骤 |
| `用户阶段` | 0基础/准备转行/已入行 | 0基础 |
| `解答的问题` | **用用户的问法写** | "智能体的知识库和模型微调有什么区别？" |
| `可信度` | 原书核对/AI生成待核/本人原创 | 本人原创 |

> **`解答的问题` 是性价比最高的一招**：让用户的口语化提问和知识片段
> 之间有直接的语言桥梁，比纯靠向量相似度稳得多。

**验收标准**：
把这块内容给你身边一个非技术朋友看，问他"看完知道下一步干什么吗"。
如果他说不知道 → 回去改。

## 阶段 1：知识库重构与上传

### 1.1 决定切片策略

| 内容类型 | 建议切片方式 | 理由 |
|---|---|---|
| 知识树 116 个知识点 | **一点一片** | 用户是按概念问的，一点一片命中率最高 |
| 六步法 / 八步法 | **一步一片** | 用户问"第三步干什么"，就该有一片正好是第三步 |
| 术语表 | **一词一片** | 术语是独立检索单元 |
| 书目资料 | **一书一片** | 避免同一本书被切散 |
| 指南类长文 | 按小标题切，每片带完整上下文 | 避免切片后语义断裂 |

**核心原则：切片方式要匹配用户的提问方式。**
用户问"第三步干什么"，就该有一片正好是"第三步"。

### 1.2 上传顺序（**这一步有个大坑**）

**先传核心内容（0.2 补写的），后传书目资料。**

**为什么**：现有书目资料量大而浅（13 本书的目录），
如果先传，检索时它会把真正有用的核心内容挤下去——
用户问"智能体怎么搭"，结果返回一堆"哪本书讲了智能体"。

**如果平台支持多知识库**：
- 知识库 A：核心内容（主线）
- 知识库 B：书目导航
- 让 Agent 优先查 A，只有用户明确问"读什么书"时才查 B

**如果平台只有一个知识库**：
在每条书目资料的元数据里打上 `内容类型=书目` 标签，
在提示词里明确写"书目资料只在用户问选书时使用"。

### 1.3 上传后必做的检查

- [ ] 上传后逐条抽查，确认**切片没有把语义切断**
- [ ] 抽查 5 条，看检索时能否被正确命中
- [ ] 确认无乱码、无格式丢失

**验收标准**：随机关掉原文，只用知识库检索，能回答出产品 0→1 五阶段和智能体六步法的内容。

## 阶段 2：智能体主体配置

### 2.1 配置清单

按顺序配置，每配一项就测一次：

| 步骤 | 动作 | 验收标准 |
|---|---|---|
| 1 | 创建应用，填写名称与简介 | 名称让零基础用户一眼看懂（"AI产品经理带路人"优于"APM-Agent-v1"） |
| 2 | 填入系统提示词 | Agent 回答符合"五段结构"（结论/类比/步骤/行动/追问） |
| 3 | 绑定知识库 | 问一个书里有的问题，能引用到 |
| 4 | 配置欢迎语 + 快捷入口 | 打开就能看到 3-4 个明确入口 |
| 5 | 选择模型 | 详见 2.2 |
| 6 | 配置开场白变量（若支持） | 能代入用户信息 |

### 2.2 选型建议

- **优先选中文表达自然、长文理解好的模型**（你的回答需要结构化输出）
- **温度值建议偏低**（0.3-0.6）：你要的是稳定、"不胡说"，
  而不是有创意。这个 Agent 的任务是教学，不是创作。
- 如果平台支持，**开启"引用来源"展示**——让用户看到答案依据，
  这对建立信任很关键（零基础用户会用"它有没有依据"来判断靠不靠谱）

## 阶段 3：测试与调优

### 3.1 测试用例（**建议 15 条，三类**）

**A 类｜核心功能（8 条）**
- [ ] "AI 产品从 0 到 1 要做哪些事？"
- [ ] "智能体怎么搭？"
- [ ] "什么是 RAG？"（术语翻译器）
- [ ] "工作流怎么配？"（**测试是否正确拦截跳步**）
- [ ] "我零基础能转行吗？"
- [ ] "帮我挑一本书"
- [ ] "知识库和微调有什么区别？"
- [ ] "我不知道该问什么"（**测试分诊台**）

**B 类｜边界与幻觉（4 条）**
- [ ] "扣子免费额度多少？"（**必须拒绝凭记忆回答**）
- [ ] "帮我写一份完整 PRD"（测试是否会假装知识库有操作细节）
- [ ] 问一个知识库完全没有的问题（测试是否坦诚说"没有"）
- [ ] 问一个前后矛盾的问题（测试是否会被带偏）

**C 类｜体验（3 条）**
- [ ] 只回一个"嗯"（测试是否会主动引导）
- [ ] 连续问 5 个不相关问题（测试是否会丢失主线）
- [ ] 表达焦虑："我 35 岁了还来得及吗？"

### 3.2 调优判断表

| 症状 | 根因 | 改哪里 |
|---|---|---|
| 答案太长、像教科书 | 提示词约束不够 | 强化"禁用清单"和字数限制 |
| 用术语不解释 | 沟通铁律没生效 | 把它提到提示词更靠前的位置 |
| 只答不追问 | 回答模板没被执行 | 检查模板第⑤项是否够具体 |
| 检索不到核心内容 | 知识库被书目资料挤占 | 见 1.2 的坑 |
| 会编造平台信息 | 护栏不够硬 | 强化"重要护栏"段，用更绝对的措辞 |
| 一次抛太多概念 | 违反"一次只讲一件事" | 加一条明确的负面示例 |

## 阶段 4：上线与迭代

### 4.1 上线前检查

- [ ] 15 条测试用例全部通过
- [ ] 用**你自己以外的一个人**实测一次（**这步最容易省，但不能省**）
- [ ] 检查欢迎语在手机端是否显示完整

### 4.2 冷启动收集反馈

你的目标用户很明确（零基础转行人群），建议：

- [ ] 找 3-5 个真实目标用户试用
- [ ] **不要问"你觉得怎么样"**（只会得到"挺好的"）
- [ ] 改问：**"你刚才有没有哪一刻不知道该说什么？"**
      这个问题能直接暴露分诊台和引导话术的问题
- [ ] 记录他们的**原话**（不要转述成你的话）——
      这些原话就是你最好的知识库 `解答的问题` 标签

### 4.3 迭代优先级

```
第一轮：修"答错"（幻觉、编造平台信息）    ← 影响信任
第二轮：修"答偏"（检索不到、跑到书目层）  ← 影响准确
第三轮：修"答得多但没用"（太长、无行动）  ← 影响体验
第四轮：优化语气和细节
```

**先修信任，再修准确，最后修体验。** 顺序不能反。

## 附：整个搭建过程的关键风险

| 风险 | 表现 | 应对 |
|---|---|---|
| **知识库被书目资料主导** | 用户问什么，都答"建议你读某本书" | 见 1.2，务必先传核心内容 |
| **资料自相矛盾被放大** | 用户问书的结构，AI 给出冲突答案 | 阶段 0.1 必须清洗 |
| **AI 生成内容再次引入错误** | 用 AI 补写核心内容，产生新的错 | 核心内容人工写；AI 只做辅助 |
| **范围蔓延** | 功能越加越多，每个都不深 | 守住 P0（分诊台 + 双主线） |
| **跳过测试直接上线** | 用户第一次用就遇到幻觉 | 15 条用例必须跑完 |
