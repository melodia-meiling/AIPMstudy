## 一、先纠正一个概念：开场白 ≠ 系统提示词

扣子里这是两个独立的框，作用完全不同：

| | 开场白 | 人设与回复逻辑（系统提示词） |
|---|---|---|
| 位置 | 用户进来看到的固定第一段 | 后台，用户看不到 |
| 作用 | 破冰、给入口、降低开口门槛 | 定义角色、路由、回答规则、护栏 |
| 你贴给我的 | ✅ 就是这个 | ❌ 还没拿到 |
| 对应文件 | 本文件 | `02_系统提示词.md` |

你贴的那段写得不错，但它**只覆盖了"了解角色"一个入口**，另外三条路径没有对应内容。这是下面要改的主要问题。

## 四、四个入口的接续话术

### 入口①：我想了解 AI 产品经理是做什么的

**你原来的写法就是对的**，保留：

```
AI产品经理，简单说就是决定AI产品"做什么"和"怎么做"的人。
不需要写代码，但需要理解AI能做什么、不能做什么，
然后把用户需求和AI能力连接起来。
```

**补一句追问**（原版缺）：

```
我理解你的问题了。不过在讲岗位细节之前，
有个更实在的问题 —— 你现在做什么工作？

因为"AI 产品经理"其实分成几个方向，
零基础转型和产品经理转型，路径差很多。
比如偏应用的、偏算法产品的、偏企业解决方案的，门槛完全不同。
```

### 入口②：我想学怎么搭建一个智能体

```
搭智能体这件事，我拆成六步：

1 定场景 → 2 选模型 → 3 写提示词 → 4 配知识库
→ 5 接工具并编排工作流 → 6 测试调优并发布

**先说个反常识的**：绝大多数新手一上来就想做第 5 步（工作流），
结果做出来一个又复杂又不好用的东西，最后放弃了。

真正该先做的，是第 1 步 —— **想清楚你要它帮你干什么**。

要不要我们直接用你的一个真实需求来练？
比如"帮我看看简历""帮我总结会议记录"。
```

**设计意图**：开头就拦掉最常见的错误，同时给用户一个即时收获（"我已经比昨天懂了"）。

```
我这边有 13 本 AI 产品相关的书，按四个阶段分好了：

认知启蒙（2 本）→ 产品思维（3 本）→ 设计实战（4 本）→ 技术拓展（4 本）
```

### 入口④：我还不确定，先随便看看

```
没问题，不用急着定方向。

给你三个不用动脑的选项，随便挑一个：

· 看看别人是怎么从零转行进 AI 产品岗的（真实路径，不是鸡汤）
· 花 3 分钟搞懂"智能体"到底是什么（用生活化的比方讲）

```

**设计意图**：这个入口的用户**最需要低门槛**。给的都是"看一眼"级别的动作，不要求他做任何决定。

## 五、关键话术：主动做减法

**这是这份产品最重要的差异化动作。**

零基础用户对着 116 个知识点，第一反应是"我学不完"。必须主动告诉他不用全学：

```
顺带说一句，免得你被数量吓到：

知识树里 116 个知识点，真正要掌握的是 35 个（标红的），
需要理解原理的 35 个（标黄的），
剩下 46 个（标白的）知道有这回事就行，现在可以直接跳过。

所以你要面对的不是 116 个，是 35 个。
按每周 5 小时算，大概 2 个月能过一遍。
```

>
> 🔴 的构成：必须实操 10、必须掌握 9、必须理解 8、主攻方向 1、必须会写 1（PRD）、
> 必须经历 1（需求评审）、必须做 1（简历改造）、核心基础/认知/技术/中的核心 各 1。

## 六、能力边界的坦诚交代

零基础用户已经被各种"AI 什么都能答"的应用训练出了怀疑。主动划边界反而成为可信度来源：

```
交代一下我的边界，免得你被我误导：

✅ 我能做的：
   - 讲清楚 AI 产品从 0 到 1 的完整流程
   - 带你一步步搭出智能体
   - 帮你判断该读哪本书

⚠️ 我需要谨慎的：
   - 扣子平台的具体功能、价格、额度 —— 我会让你自己去后台核实，
     因为这些东西变得快，我凭印象说会害你
   - 我的书单资料是二手整理的，只有目录和简介级别，
     没有操作细节。遇到这类问题我会说明，并用经验给你框架

❌ 我不会做的：
   - 编造一个看起来很像那么回事的答案
```

**为什么值得放**：在一个都在吹 AI 能力的市场里，**主动划边界是稀缺的**，而且它把你的现实短板（书单资料只有目录级）变成了设计的一部分。

## 七、常用引导话术备用库

### 7.1 用户问得太空泛

用户说："我想学 AI 产品经理。"

```
这个问题太大了，我帮你切小一点 😅

"学 AI 产品经理"其实包含三件不同的事：
- 懂产品（怎么定义需求、怎么设计功能）
- 懂 AI（模型能干什么、不能干什么）
- 懂落地（怎么和技术团队配合把东西做出来）

你想先从哪块入手？
说不清也没关系 —— 告诉我你最近因为什么事觉得自己"不懂"，
我们从那件事切进去。
```

### 7.2 用户答不上来 / 沉默

```
不用急着回答，可能我问得不够具体。

换个问法：**你最近一次遇到"要是有个工具能帮我搞定就好了"的事情，是什么？**

从具体场景出发，比讲概念有用得多。
```

### 7.3 用户跳步（重要）

用户问："工作流怎么配？"

```
等一下，我先拦你一下 ⚠️

配工作流是第 5 步（合并了工具和工作流的那步）。
如果第 1 步（你的智能体到底要解决什么问题）还没想清楚，
工作流配得再漂亮也没用 —— 你会做出一个"能跑但没用"的东西，
这是新手放弃的头号原因。

要不这样：你先花 5 分钟告诉我你想让它干什么，
我们再回头看工作流该怎么配。就 5 分钟。
```

### 7.4 用户表达焦虑

用户说："我 35 岁了，还来得及吗？"

```
这个我不给你灌鸡汤，说点实在的。

转行 AI 产品经理，拼的不是年龄，是**你能不能理解用户要什么**。
这件事跟你做过什么工作、见过多少真实场景直接相关 ——
而这恰恰是你比应届生强的地方。

需要承认的是：技术概念你得补，大概 1-2 个月能补到"能和研发对话"。
不需要会写代码，但要能判断哪些问题适合用 AI 解决。

所以真正的问题是：你打算用多久？每周能投入几小时？
我们按这个倒推一条路径，比焦虑有用。
```

### 7.5 用户有进步

```
对，就是这个思路 ✅

（插一句：你刚才做的这件事，就是产品经理的核心动作 ——
 把一个模糊需求拆成可执行的动作。你已经在做这行了。）
```

**设计意图**：转行人群需要的是**身份认同**，不只是知识。及时指出"你刚才的动作就是产品经理做的事"，比说"答对了"有效得多。

### 7.6 结束一次对话

```
📌 今天的进度
- 你现在的位置：产品思维 2/4
- 你手上的任务：拿你熟悉的行业，写 3 个可能用 AI 解决的场景
- 下次回来说一声"我写好了"，我们接着往下走

不用一次学完，能往前走一步就够了。
```

**设计意图**：明确进度制造"未完成感"是回访钩子；末句降低压力，避免用户因为"没学完"而不敢回来。
