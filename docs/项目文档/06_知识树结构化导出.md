## 🏢 行业&业务认知

### 💼 岗位分类

### AI应用产品经理 (AI Application PM)

- **掌握程度**：主攻方向
- **解释**：做上层AI应用、智能体、工作流的产品经理，不碰模型训练。零基础转行主攻方向。核心是把大模型能力落地到业务场景。
- **关联**：Agent、RAG、Coze
- **路径**：行业&业务认知 / 岗位分类 / AI应用产品经理

### 大模型算法产品经理 (LLM Algorithm PM)

- **掌握程度**：门槛高
- **解释**：偏模型训练、调优、评测，需要算法背景，不适合零基础转行。
- **关联**：微调、SFT
- **路径**：行业&业务认知 / 岗位分类 / 大模型算法产品经理

### AI解决方案产品经理 (AI Solution PM)

- **掌握程度**：可考虑
- **解释**：面向企业客户，把AI能力包装成行业解决方案，需要懂业务+懂AI能力边界。
- **关联**：ToB、SaaS
- **路径**：行业&业务认知 / 岗位分类 / AI解决方案产品经理

### 💰 业务模式

### ToC (to Customer)

- **掌握程度**：了解
- **解释**：面向个人用户的AI产品，如AI聊天、AI剪辑、AI学习工具。靠流量、会员、广告变现。
- **关联**：SEO、GEO
- **路径**：行业&业务认知 / 业务模式 / ToC

### ToB (to Business)

- **掌握程度**：重点关注
- **解释**：面向企业客户的AI产品，如企业办公助手、行业智能体。客单价高、续费稳定。工程+项目管理背景在此赛道有差异化优势。
- **关联**：SaaS、Agent
- **路径**：行业&业务认知 / 业务模式 / ToB

### SaaS (Software as a Service)

- **掌握程度**：了解
- **解释**：软件即服务，云端部署，客户按年/月付费使用，不用自己安装部署。绝大多数AI企业产品都是SaaS模式。
- **关联**：ToB
- **路径**：行业&业务认知 / 业务模式 / SaaS

### 📈 流量与增长

### SEO (Search Engine Optimization)

- **掌握程度**：了解
- **解释**：搜索引擎优化。针对百度、谷歌，让网页排到搜索结果前面，拿到点击流量。核心：关键词、外链、网页权重。
- **关联**：SEM、GEO
- **路径**：行业&业务认知 / 流量与增长 / SEO

### GEO (Generative Engine Optimization)

- **掌握程度**：新兴概念
- **解释**：生成式引擎优化。针对豆包、DeepSeek、Kimi等大模型，让AI回答用户问题时主动引用你的品牌/内容。AI时代新玩法，核心：内容权威、结构化、事实准确。
- **关联**：SEO、RAG
- **路径**：行业&业务认知 / 流量与增长 / GEO

### SEM (Search Engine Marketing)

- **掌握程度**：了解
- **解释**：搜索引擎付费广告，花钱买搜索页面广告位，和SEO免费自然排名对应。
- **关联**：SEO
- **路径**：行业&业务认知 / 流量与增长 / SEM


## 📋 产品基础能力

### 📝 产品文档体系

### PRD (Product Requirement Document)

- **掌握程度**：必须会写
- **解释**：产品需求文档。产品经理最核心输出物，写清楚：做什么功能、给谁用、页面长什么样、点按钮发生什么、异常怎么处理。开发、设计、测试全部照此干活。
- **关联**：BRD、MRD、MVP、Axure、Figma
- **路径**：产品基础能力 / 产品文档体系 / PRD

### BRD (Business Requirement Document)

- **掌握程度**：了解
- **解释**：商业需求文档。偏高层，讲为什么做这个产品、市场机会、商业模式、盈利预期，给老板和投资人看。
- **关联**：PRD、MRD
- **路径**：产品基础能力 / 产品文档体系 / BRD

### MRD (Market Requirement Document)

- **掌握程度**：了解
- **解释**：市场需求文档。讲目标用户、市场规模、竞品分析、用户痛点，介于BRD和PRD之间。
- **关联**：BRD、PRD
- **路径**：产品基础能力 / 产品文档体系 / MRD

### MVP (Minimum Viable Product)

- **掌握程度**：必须理解
- **解释**：最小可行产品。先做功能最简单但能跑通核心逻辑的版本，验证需求是否成立，再迭代完善。
- **关联**：PRD、敏捷开发
- **路径**：产品基础能力 / 产品文档体系 / MVP

### ⚙️ 技术基础概念

### 前端 (Frontend)

- **掌握程度**：看懂
- **解释**：用户眼睛看得见、手能点的一切。网页页面、按钮、弹窗、APP界面。前端工程师负责把界面做出来。
- **关联**：后端、UI/UX、HTML
- **路径**：产品基础能力 / 技术基础概念 / 前端

### 后端 (Backend)

- **掌握程度**：看懂
- **解释**：用户看不见的后台。存数据、调用大模型、计算逻辑。发消息到服务器、调用大模型运算、返回回答，整套看不见的逻辑就是后端。
- **关联**：前端、数据库、API
- **路径**：产品基础能力 / 技术基础概念 / 后端

### 数据库 (Database)

- **掌握程度**：了解
- **解释**：存数据的地方。用户信息、聊天记录、产品数据都存在数据库里。常见MySQL、PostgreSQL。
- **关联**：后端、向量数据库
- **路径**：产品基础能力 / 技术基础概念 / 数据库

### API (Application Programming Interface)

- **掌握程度**：必须理解
- **解释**：应用程序编程接口。通俗说就是大模型的'调用通道'，产品要用大模型能力就通过API调用，不用自己从零做大模型。按调用量/Token计费。
- **关联**：SDK、Token、后端、HTTP、JSON
- **路径**：产品基础能力 / 技术基础概念 / API

### SDK (Software Development Kit)

- **掌握程度**：了解
- **解释**：软件开发工具包。比API更完整的一套工具，方便开发者快速把AI能力嵌入自己的APP/系统。
- **关联**：API
- **路径**：产品基础能力 / 技术基础概念 / SDK

### UI / UX (User Interface / User Experience)

- **掌握程度**：了解
- **解释**：UI=用户界面（外观、按钮、布局）；UX=用户体验（用起来的流畅度、逻辑感受）。AI产品以对话交互、流式输出为主，UX权重更高。
- **关联**：前端、流式输出、Figma
- **路径**：产品基础能力 / 技术基础概念 / UI / UX

### HTML (HyperText Markup Language)

- **掌握程度**：理解
- **解释**：超文本标记语言，构建网页结构的语言，不是编程语言。所有网页底层都是HTML写的，浏览器把HTML代码渲染成可视化页面。HTML管结构，CSS管样式，JavaScript管交互。
- **关联**：前端、CSS、JavaScript
- **路径**：产品基础能力 / 技术基础概念 / HTML

### 命令行 / Bash (Bash / Shell)

- **掌握程度**：了解
- **解释**：Bash是一种命令行解释器，就是程序员在黑色终端窗口里输入命令的环境。Linux和Mac默认自带。程序员用命令行运行代码、安装工具、操作文件、部署项目。产品经理不需要会写命令，知道'终端/命令行'是程序员敲命令干活的地方就行。
- **关联**：后端、部署、批处理文件
- **路径**：产品基础能力 / 技术基础概念 / 命令行 / Bash

### 批处理文件 .bat/.sh (Batch / Shell Script)

- **掌握程度**：了解
- **解释**：.bat是Windows的批处理文件，.sh是Mac/Linux的脚本文件。里面写了一串命令，双击或运行就能自动依次执行。程序员常用它做自动化操作，如一键部署、一键备份。
- **关联**：命令行/Bash、部署
- **路径**：产品基础能力 / 技术基础概念 / 批处理文件 .bat/.sh

### JSON (JavaScript Object Notation)

- **掌握程度**：理解
- **解释**：一种通用的数据格式，用键值对组织数据，如{"姓名":"张三","年龄":25}。人能看懂程序也能看懂，是前后端之间传数据、API返回结果的标准格式。产品经理能看懂结构就行。
- **关联**：API、后端、前端
- **路径**：产品基础能力 / 技术基础概念 / JSON

### HTTP (HyperText Transfer Protocol)

- **掌握程度**：理解
- **解释**：超文本传输协议，浏览器和服务器之间通信的'交通规则'。打开网页、调用API底层都是HTTP在传数据。常见请求：GET（获取数据）、POST（提交数据）。常见状态码：200成功、404找不到、500服务器错误、401没权限。
- **关联**：API、后端、前端
- **路径**：产品基础能力 / 技术基础概念 / HTTP

### 全盘加密 FDE (Full-Disk Encryption)

- **掌握程度**：了解
- **解释**：一种安全技术，把整个硬盘的数据全部加密，没有密码即使拿到电脑也读不到数据。Mac的FileVault、Windows的BitLocker都是FDE。做ToB企业产品、涉及敏感数据时客户经常会问。
- **关联**：后端、数据库、ToB
- **路径**：产品基础能力 / 技术基础概念 / 全盘加密 FDE

### 🔄 项目协作流程

### 敏捷开发 (Agile)

- **掌握程度**：了解
- **解释**：小步快跑、快速迭代的工作方式。把大需求拆成小周期（通常2周一个Sprint），先做核心功能，快速上线验证，再持续优化。
- **关联**：MVP、迭代
- **路径**：产品基础能力 / 项目协作流程 / 敏捷开发

### 需求评审 (Requirement Review)

- **掌握程度**：必须经历
- **解释**：产品经理讲PRD，开发、设计、测试一起评估可行性、工作量、风险，确认后才进入开发。
- **关联**：PRD
- **路径**：产品基础能力 / 项目协作流程 / 需求评审

### AB测试 (A/B Testing)

- **掌握程度**：理解
- **解释**：把用户分成两组，分别用不同方案，看数据哪个效果好，用数据决策而不是拍脑袋。AI产品常用：测试不同Prompt策略对输出质量的影响。
- **关联**：Prompt、评测
- **路径**：产品基础能力 / 项目协作流程 / AB测试

### FDE特性驱动开发 (Feature-Driven Development)

- **掌握程度**：了解
- **解释**：一种软件开发方法论，和敏捷开发类似，核心是围绕'功能特性'组织开发。把大项目拆成一个个小的功能特性（如用户登录、合同上传），每个特性独立设计、开发、测试、交付。JD里出现FDE基本都是这个意思。
- **关联**：敏捷开发、需求评审、MVP
- **路径**：产品基础能力 / 项目协作流程 / FDE特性驱动开发

### 🎨 原型设计工具

### Axure (Axure RP)

- **掌握程度**：必须掌握
- **解释**：专业的交互原型设计工具，产品经理老牌标配。能画出可点击的APP/网页原型（点按钮能跳转、能输入、能弹窗），还能直接写PRD文档。国内传统互联网公司和大厂用得多。
- **关联**：PRD、Figma、需求评审、前端
- **路径**：产品基础能力 / 原型设计工具 / Axure

### Figma (Figma)

- **掌握程度**：必须掌握
- **解释**：云端协作设计工具，近几年最火。最大特点：多人实时协作（像在线文档）、浏览器就能用、组件化设计、UI设计能力强。免费版够用，产品经理和设计师都在用。
- **关联**：Axure、PRD、UI/UX、前端
- **路径**：产品基础能力 / 原型设计工具 / Figma


## 🤖 AI专属技术知识

### 🧠 大模型基础

### LLM (Large Language Model)

- **掌握程度**：核心基础
- **解释**：大语言模型，俗称大模型。豆包、DeepSeek、Kimi、GPT的核心本体，经过海量数据训练，能理解和生成人类语言、做逻辑推理的AI底座。产品经理不用懂怎么训练，重点搞懂能做什么、不能做什么。
- **关联**：GPT、开源/闭源、幻觉、Token
- **路径**：AI专属技术知识 / 大模型基础 / LLM

### GPT (Generative Pre-trained Transformer)

- **掌握程度**：了解
- **解释**：生成式预训练Transformer。原本是OpenAI的大模型系列名（如GPT-4o），现在行业也泛指所有生成式大模型。OpenAI是开发GPT的公司，全球标杆。
- **关联**：LLM、Codex
- **路径**：AI专属技术知识 / 大模型基础 / GPT

### 开源 / 闭源模型 (Open-source / Closed-source)

- **掌握程度**：理解
- **解释**：闭源：不公开代码参数，只能通过网页/API调用（GPT、豆包、Kimi）；开源：公开代码参数，可免费下载自己部署修改（DeepSeek开源、Llama）。选底座时判断：闭源省心效果好按调用付费；开源可控性强适合数据敏感场景。
- **关联**：LLM、API
- **路径**：AI专属技术知识 / 大模型基础 / 开源 / 闭源模型

### 幻觉 (Hallucination)

- **掌握程度**：核心认知
- **解释**：大模型天生特性——一本正经编造事实、说错数据、输出错误内容，俗称AI胡说八道。AI产品经理最重要工作之一：设计方案（RAG、溯源、人工审核）减少幻觉，控制风险。
- **关联**：RAG、溯源、BadCase
- **路径**：AI专属技术知识 / 大模型基础 / 幻觉

### Token (Token)

- **掌握程度**：理解
- **解释**：大模型计算输入输出的计量单位，简单理解就是字词数量（1token≈0.7个汉字）。调用API按Token计费，输入输出越长花钱越多。做产品成本估算时用到。
- **关联**：API、LLM
- **路径**：AI专属技术知识 / 大模型基础 / Token

### AGI (Artificial General Intelligence)

- **掌握程度**：概念了解
- **解释**：通用人工智能。能像人一样学会各类任务的AI。行业普遍认为具身智能是通往AGI的重要路线。
- **关联**：具身智能
- **路径**：AI专属技术知识 / 大模型基础 / AGI

### 🔧 核心技术能力

### Prompt (Prompt / 提示词)

- **掌握程度**：必须掌握
- **解释**：你给大模型发的所有输入——问题、指令、要求、背景资料都叫Prompt。AI产品经理不是专职写Prompt的，而是把优质Prompt封装进产品，让普通用户不用研究指令也能用好AI。
- **关联**：CoT、AB测试
- **路径**：AI专属技术知识 / 核心技术能力 / Prompt

### CoT (Chain of Thought / 思维链)

- **掌握程度**：理解
- **解释**：让大模型一步步思考的提示技巧，不让它直接给答案，先写推理过程，大幅提升计算、逻辑类问题准确率。
- **关联**：Prompt
- **路径**：AI专属技术知识 / 核心技术能力 / CoT

### RAG (Retrieval-Augmented Generation)

- **掌握程度**：核心技术
- **解释**：给大模型外接私有资料库，回答时先去库里搜索匹配资料，再基于资料生成答案。是目前解决大模型胡说八道、不懂内部数据、信息过时的最主流方案。
- **关联**：向量数据库、Embedding、幻觉、溯源
- **路径**：AI专属技术知识 / 核心技术能力 / RAG

### Embedding (Embedding / 向量嵌入)

- **掌握程度**：了解
- **解释**：把文字、图片转换成计算机能看懂的数字（向量），让AI识别语义相似度。是语义搜索、RAG知识库的底层技术。实现'搜意思'而非'搜关键词'。
- **关联**：RAG、向量数据库
- **路径**：AI专属技术知识 / 核心技术能力 / Embedding

### 向量数据库 (Vector Database)

- **掌握程度**：了解
- **解释**：专门存向量数字的数据库，可快速从海量资料里找到语义最匹配的内容，是RAG系统的标配组件。
- **关联**：RAG、Embedding、数据库
- **路径**：AI专属技术知识 / 核心技术能力 / 向量数据库

### 微调 / SFT (Fine-tuning / Supervised Fine-Tuning)

- **掌握程度**：理解
- **解释**：拿一批专属领域数据，在现成大模型基础上再小范围训练，让它更适配特定行业/风格。成本比RAG高、周期长。大部分场景用RAG就够，只有对风格/专业度要求极高时才需要微调。
- **关联**：RAG、LLM
- **路径**：AI专属技术知识 / 核心技术能力 / 微调 / SFT

### 插件 / 工具调用 (Plugin / Tool)

- **掌握程度**：理解
- **解释**：让大模型不止能聊天，还能调用外部能力：读PDF、查实时网页、做表格计算、生成图片、连接企业系统。
- **关联**：Agent、MCP、API
- **路径**：AI专属技术知识 / 核心技术能力 / 插件 / 工具调用

### 溯源 / 引用标注 (Grounding)

- **掌握程度**：理解
- **解释**：AI输出答案时标注内容来自知识库哪一页、哪份资料，提升可信度方便核对，是减少幻觉的常用手段。做企业知识库、法律/工程类AI产品必备。
- **关联**：RAG、幻觉
- **路径**：AI专属技术知识 / 核心技术能力 / 溯源 / 引用标注

### 流式输出 (Streaming)

- **掌握程度**：了解
- **解释**：大模型像打字机一样一个字一个字逐步显示结果，而不是等全部生成完才一次性显示。现在AI对话产品的标配交互。
- **关联**：UI/UX、前端
- **路径**：AI专属技术知识 / 核心技术能力 / 流式输出

### 🤝 智能体与工作流

### Agent (Agent / 智能体)

- **掌握程度**：核心中的核心
- **解释**：不是简单一问一答的聊天机器人，而是能自主拆解任务、调用工具、多步骤完成复杂工作的AI。核心组成：角色设定、记忆、任务规划、工具调用、结果反思。

### 接口 / API (API)

- **掌握程度**：必须理解
- **解释**：程序之间通信的通道。前端调后端接口拿数据，后端调大模型接口拿回答。和后端沟通时，'这个功能需要几个接口''接口返回什么字段'是高频对话。
- **关联**：API、后端、前端、HTTP
- **路径**：Python编程基础（产品经理向） / 沟通必备术语 / 接口 / API

### 参数 / 入参 (Parameters / Input)

- **掌握程度**：理解
- **解释**：调用函数或接口时传进去的数据。比如调用'提取合同信息'函数，传入的合同文件就是参数。和后端沟通时会说'这个接口需要传什么参数'。
- **关联**：函数def、API、Python
- **路径**：Python编程基础（产品经理向） / 沟通必备术语 / 参数 / 入参

### 返回值 / 出参 (Return Value / Output)

- **掌握程度**：理解
- **解释**：函数或接口执行完返回的结果。比如调大模型接口，返回的回答文本就是返回值。产品经理要关注'返回的数据格式对不对、有没有包含需要的字段'。
- **关联**：函数def、API、JSON、Python
- **路径**：Python编程基础（产品经理向） / 沟通必备术语 / 返回值 / 出参

### 异常处理 try/except (try/except)

- **掌握程度**：理解
- **解释**：程序出错时的兜底机制。try里写正常逻辑，except里写'出错了怎么办'。比如调大模型超时了，except里可以写'重试3次还是失败就提示用户稍后再试'。产品经理设计异常场景时，后端就是用这个实现的。
- **关联**：Python、BadCase、PRD
- **路径**：Python编程基础（产品经理向） / 沟通必备术语 / 异常处理 try/except

### 日志 log (Log)

- **掌握程度**：了解
- **解释**：程序运行时记录的信息，比如'用户XXX上传了合同''调用接口耗时2秒''出错了：原因是XXX'。排查问题时后端会查日志。产品经理反馈bug时，提供时间点和操作步骤，后端就能去查对应日志。

- **解释**：找到聊天补全接口，看请求地址、参数、返回格式。核心参数：model用哪个模型、messages对话内容（system人设+user问题）、temperature随机性（0稳定1创意）。

### 调用API (Call API)

- **掌握程度**：理解
- **解释**：用Python requests.post发HTTP请求，传headers身份验证和json参数（model+messages），拿到response.json()结果。运行逻辑：代码发HTTP请求→大模型服务器运算→返回JSON结果→程序解析展示。这是所有AI产品的底层逻辑。
- **关联**：API、HTTP、JSON、Python、requests
- **路径**：实操从0到1全流程 / 调用大模型API / 调用API

### 处理返回结果 (Handle Response)

- **掌握程度**：理解
- **解释**：大模型返回的是文字，按格式解析提取需要的字段；用Prompt要求返回JSON格式方便解析；出错处理（调用失败/超时/格式不对）要有兜底。
- **关联**：API、JSON、异常处理、Python
- **路径**：实操从0到1全流程 / 调用大模型API / 处理返回结果

- **解释**：输入Token+输出Token×单价=本次费用。比如一份合同5000字≈3500Token，提取一次成本不到1分钱。
