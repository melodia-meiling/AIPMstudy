# 新增后端接口文档（5 个端点 · 8 个方法）

> 全部为**相对路径**调用（`/api/xxx`），与现有 server.js 一致，不写 host。
> 全部纳入**多用户隔离**（按 httpOnly Cookie 的 `aipm_uid` 区分），
> 每个浏览器看到的是自己的数据。
> 接口清单从运行中的服务实测提取，非手写。

## 二、`GET /api/stats` — 仪表盘聚合

无参数。所有数值由真实数据计算，**没有任何写死的示例值**。

### 返回结构

```
{
  ok: true,
  generatedAt: "2026-09-12T05:12:00.000Z",

  today: {
    date: "2026-09-12",
    events: 0,              // 今日学习事件数
    minutes: 0,             // 估算学习时长（分钟）
    minutesIsEstimate: true,// 明确标注这是估算值
    perEventMinutes: 6,     // 折算系数：每事件 6 分钟
    learned: 0, notes: 0, quizzes: 0, docs: 0
  },

  totals: {
    docs: 240,              // 知识库总条目
    learned: 0,             // 已学知识点数
    noted: 0,               // 有笔记的知识点数
    enrichEntries: 0,       // AI 补全条目数
    wrong: 0,               // 错题数
    newKnowledge: 0,        // 新知识数
    portfolio: 0,           // 作品数
    quizDocs: 0,            // 已生成题目的知识点数
    quizQuestions: 0,       // 题目总数
    activityEvents: 0,      // 历史活动总事件数
    activeDays: 0,          // 有学习记录的天数
    streak: 0               // 连续打卡天数
  },

  byMark: {                 // 按掌握程度分档
    "🔴": { total: 38,  learned: 0 },
    "🟡": { total: 53,  learned: 0 },
    "⚪": { total: 121, learned: 0 },
    "无": { total: 28,  learned: 0 }
  },

  goal: {                   // 今日目标
    text: "",
    targetTasks: 4,
    done: 0,                // = today.events
    isCustom: false         // false 表示用户还没自定义过
  },

  plan: {                   // 成长计划（四阶段）
    stages: [
      { key: "cognition", name: "认知启蒙", docs: 121, learned: 0 },
      { key: "product",   name: "产品思维", docs: 53,  learned: 0 },
      { key: "design",    name: "设计实战", docs: 38,  learned: 0 },
      { key: "tech",      name: "技术拓展", docs: 28,  learned: 0 }
    ],
    overall: 0              // 整体进度百分比
  },

  recent: [ { date: "2026-09-12", events: 0, minutes: 0 } ]  // 近 14 天
}
```

### 数据口径说明（重要，别误解）

| 字段 | 口径 |
|---|---|
| `today.minutes` | **估算值**。由「今日活动事件数 × 6 分钟」折算，不是真实计时。接口同时返回 `minutesIsEstimate: true` 和 `perEventMinutes`，前端应标注"估算" |
| `plan.overall` | 已学数 ÷ 知识库总数 |
| `streak` | 从今天往回数，连续有学习记录的天数 |
| `recent` | 固定返回 14 天，无记录的日期也会出现（events=0），方便直接画图 |

## 三、`GET /api/checkins` — 打卡记录

### 参数

| 名称 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `days` | query | `120` | 向前追溯的天数 |

例：`/api/checkins?days=30`

### 返回结构

```
{
  ok: true,
  total: 3,
  activitySource: "activity",   // 或 "derived"
  days: [
    {
      date: "2026-09-12",
      events: 4,
      minutes: 24,
      kinds: { learn: 2, note: 1, wrong: 1 },   // 各类型事件数
      titles: ["RAG", "Agent"]                  // 当天涉及的知识点标题（最多 6 个）
    }
  ]
}
```

### `activitySource` 两种取值

- `activity`：来自显式活动流（**推荐状态**）。每次写操作会自动追加一条活动记录
- `derived`：活动流为空时的**兜底**——从 `learned` / `notes` / `wrong` 自带的时间戳推导。覆盖面不如 `activity` 全（例如答对的题目不会留下痕迹）

> 活动流是自动记录的：在请求结束前做「请求前后差量比对」，
> 所以 `note` / `learned` / `quiz` / `enrich` / `wrong` / `portfolio`
> 等所有写操作都会被覆盖，新增写接口也自动生效。

## 五、`POST /api/goals` — 存今日目标

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `text` | string | 否 | 截断到 200 字 |


```json
{ "ok": true, "text": "完成 PRD 撰写练习", "targetTasks": 5 }
```

## 七、`POST /api/portfolio` — 新增作品

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | string | **是** | 截断到 80 字；为空返回 400 |
| `type` | string | 否 | 默认 `practice`，截断到 20 字 |
| `docId` | string | 否 | 关联知识点 id（如 `d40`），会自动带出该知识点标题 |
| `summary` | string | 否 | 截断到 600 字 |
| `link` | string | 否 | 截断到 400 字 |

### 返回 / item 结构

```json
{
  "ok": true,
  "item": {
    "id": "mtxxhqp5g85wgz",
    "title": "接口文档示例作品",
    "type": "agent",
    "docId": "d40",
    "docTitle": "AI 原生应用 vs AI 辅助应用",
    "summary": "示例",
    "link": "https://example.com",
    "at": "2026-09-12T05:12:16.745Z"
  }
}
```

> `docTitle` 是**服务端自动补的**，前端不用自己查。

## 九、`POST /api/playground` — API 实验

在当前服务里**真实发起一次 HTTP 请求**，把结果原样回显。

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `url` | string | **是** | 必须以 `http://` 或 `https://` 开头 |
| `method` | string | 否 | 默认 `GET`；支持 `GET/POST/PUT/PATCH/DELETE` |
| `headers` | object | 否 | 自定义请求头；键名只允许 `[A-Za-z0-9-]`，值截断 2000 字 |
| `body` | string \| object | 否 | 非 GET/DELETE 时发送；对象会自动 JSON 序列化 |
| `apiKey` | string | 否 | 会作为 `Authorization: Bearer <key>` 发送 |
| `allowPrivate` | boolean | 否 | 默认 `false`。见下方安全约束 |

### 成功返回

```json
{
  "ok": true,
  "request": { "method": "GET", "url": "...", "headerKeys": ["Accept"] },
  "status": 200,
  "statusText": "OK",
  "headers": { "content-type": "application/json", "date": "..." },
  "bodyText": "…",        // 截断到 60000 字符
  "bodyJson": { },        // 能解析成 JSON 时给出解析结果，否则为 null
  "truncated": false,
  "elapsedMs": 9
}
```

### 失败返回（注意：也用 HTTP 200，靠 `ok` 区分）

```json
{
  "ok": false,
  "request": { "method": "GET", "url": "..." },
  "error": "请求超时（15 秒）",
  "elapsedMs": 15000,
  "hint": "无法连接目标地址。常见原因：域名写错、目标服务不可达、或该地址需要代理。"
}
```

### 参数错误（HTTP 400）

```json
{ "error": "URL 必须以 http:// 或 https:// 开头" }
```

```json
{
  "error": "出于安全考虑，默认不允许请求内网 / 本机地址。确实需要请勾选\"允许内网地址\"。",
  "code": "PRIVATE_HOST_BLOCKED"
}
```

### 安全约束（已实现）

| 约束 | 说明 |
|---|---|
| 协议白名单 | 只允许 http / https |
| **SSRF 防护** | 默认拒绝 `localhost` / `127.*` / `10.*` / `192.168.*` / `172.16-31.*` / `169.254.*` / `*.internal` / `*.local`；需显式传 `allowPrivate: true` |
| 超时 | 15 秒，超时返回结构化错误 |
| 响应截断 | 最多 60KB，超出置 `truncated: true` |
| 敏感头过滤 | `set-cookie` / `authorization` / `proxy-authorization` **不回显** |
| 密钥处理 | 传入的 `apiKey` 只用于本次请求头，不落盘、不回显（仅返回 `headerKeys` 键名列表） |

## 十、前端调用示例

```js
// 全部相对路径，不需要拼 host
const get = (p) => fetch(p).then(r => r.json());
const post = (p, d) => fetch(p, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(d),
}).then(r => r.json());

// 仪表盘
const stats = await get('/api/stats');

// 打卡（近 30 天）
const checkins = await get('/api/checkins?days=30');

// 今日目标
await post('/api/goals', { text: '完成 3 道刷题练习', targetTasks: 5 });

// 作品集
const { items } = await get('/api/portfolio');
await post('/api/portfolio', { title: '合同提取智能体', type: 'agent', docId: 'd40' });
await fetch('/api/portfolio?id=' + id, { method: 'DELETE' });

// API 实验
const r = await post('/api/playground', {
  url: 'https://api.deepseek.com/models',
  method: 'GET',
  apiKey: 'sk-xxx',
});
if (r.ok) console.log(r.status, r.elapsedMs + 'ms', r.bodyJson);
else console.log('失败：', r.error);
```

> **Cookie 说明**：服务端靠 `aipm_uid` Cookie 识别用户，浏览器会自动携带，
> 前端不需要做任何处理。用 curl / Node 测试时需要自己维护 Cookie 才能看到同一用户的数据。

## 十一、前端页面 ↔ 接口对照表

新前端（`public/` 下三个文件）一共 7 个页面，每个页面对接的接口如下。
**页面里没有任何写死的示例数字**，所有数字都来自下面这些接口。

| 页面 | 用到的接口 | 页面上能看到什么 |
|---|---|---|
| 仪表盘主页 | `GET /api/stats`<br>`GET /api/goals`<br>`POST /api/goals`<br>`POST /api/chat`（SSE） | 今日学习总览气泡、近 14 天迷你日历、今日目标进度环、我的练习 5 条进度、成长计划 4 阶段、AI Tutor |
| 知识库文档 | `GET /api/tree`<br>`GET /api/doc?id=`<br>`GET /api/search?q=`<br>`POST /api/note`<br>`POST /api/learned`<br>`POST /api/ask`（SSE）<br>`POST /api/enrich`（SSE）<br>`POST /api/websearch`<br>`GET/DELETE /api/newknowledge` | 左侧三级知识树（✓已学 / ✎有笔记 / +N有补充）、知识点详情、全局语义检索、笔记自动保存、标记已学、AI 答疑、AI 补全、新知识弹窗 |
| 刷题中心 · 客观题 | `GET /api/quiz?id=`<br>`POST /api/quiz/generate`<br>`POST /api/quiz/submit`<br>`GET/DELETE /api/wrong` | 选知识点 → AI 出 3 道单选题 → 作答交卷 → 得分与逐题解析；错题自动进错题本，可逐条移除或清空 |
| 刷题中心 · 主观题（新增） | `POST /api/ask`（SSE）<br>`POST /api/websearch`<br>`GET/POST/DELETE /api/newknowledge` | 四步：选方向（PRD 撰写 / 提示词优化）与知识点 → 生成练习题（可联网拿真实案例做背景）→ 写简略思路 → 拿到①规范完整版②缺失要素③结构拆解三段反馈；可改完再提交做第二版迭代 |

> **主观题模块没有新增接口**，四个能力全部复用上表里已有的端点：
>
> | 要做的事 | 复用的接口 | 关键参数 |
> |---|---|---|
> | 生成练习题 | `POST /api/ask` | `{ id: 知识点id, question: 出题指令, webMode: 'always' \| 'never' }` |
> | 取真实行业案例 | `POST /api/websearch` | `{ query, count: 5 }`（不调大模型） |
> | 三段反馈 | `POST /api/ask` | `{ id, question: 题目+我的思路+格式要求, history: 上一版问答, webMode: 'auto' }` |
> | 保存 / 读取 / 删除练习记录 | `POST/GET/DELETE /api/newknowledge` | `tags` 里带 `主观题练习` 作为筛选标记 |
>
> 保存练习记录时用到的一点副作用：`POST /api/newknowledge` 的新增会被服务端的活动流
> 记成一条学习事件（`kind=newknowledge`），所以练习次数会自动进入 `/api/stats` 的
> 今日事件 / 估算时长 / 连续打卡——这就是「练习数据同步到整体学习统计」的实现方式。
| API 实验 | `POST /api/playground` | 在服务端真实发一次 HTTP 请求，展示状态码 / 耗时 / 响应头（已剥离 set-cookie）/ 响应体（JSON 自动格式化） |
| 任务日历 | `GET /api/checkins?days=N` | 近 30/60/120 天的打卡格子（按事件数分四档着色）+ 最近 30 条学习记录（含事件类型与涉及的知识点） |
| 项目作品集 | `GET/POST/DELETE /api/portfolio` | 作品卡片（类型 / 时间 / 关联知识点 / 外部链接），可新增、删除 |
| 设置 | `GET/POST /api/settings` | 联网模式（自动判断 / 每次都联网 / 从不联网）、搜索服务商与 Key、笔记自动补全开关、学习代号 |

另外两个接口不直接对应页面，是开发自查用：

| 接口 | 用途 |
|---|---|
| `GET /api/catalog` | 只返回知识目录，不调大模型 |
| `GET /api/progress` | 学习进度总览（`/api/stats` 已覆盖，保留兼容） |

> **前端一致性由脚本守住**：`tools/verify_frontend.mjs` 会检查
> 「app.js 里调用的每个 `/api/xxx` 在 server.js 里都有对应路由」，
> 以及「app.js 引用的每个 DOM id 都能被创建」。
> 端到端验证 `tools/verify_ui_e2e.mjs` 则会真实执行前端并逐页点击。
